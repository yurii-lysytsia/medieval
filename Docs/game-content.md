# Дані гри та балансування

Увесь стартовий контент MVP зберігається в `Medieval/Domain/Resources/MVPConfiguration.json`.
Щоб змінити ціну, дохід, модифікатор, характеристики юніта або стартові умови, редагуйте
цей файл — ігрові правила для цього не змінюються.

Під час створення нової партії `GameStore` завантажує конфігурацію через
`GameContentLoader`. Перед поверненням даних завантажувач запускає
`GameContentValidator`, який перевіряє:

- унікальність ідентифікаторів;
- посилання між даними світу;
- числові межі;
- розміщення армій лише на прохідних гексах, а міст — лише на придатних для забудови.

Прохідність задається один раз — у типі місцевості. Гекс лише посилається на
місцевість (`terrainID`) і власної копії не має, тож суперечність між ними
неможлива за побудовою. Читати прохідність слід через
`GameContentConfiguration.isPassable(_:)`.

Для кожного з восьми типів місцевості конфігурація також зберігає ціну руху,
оборонний модифікатор і ознаку можливості заснувати місто. Це дає змогу змінювати
тактичні властивості гексів без редагування правил або інтерфейсу.

Некоректний файл зупиняє створення партії з конкретним повідомленням для розробника.
Тести в `Tests/MedievalDomainTests` охоплюють приклад повної конфігурації та кожен
клас помилок валідації.

Нова партія починається у фазі `capitalPlacement`: кожен гравець по черзі ставить
одну столицю на вільний гекс, придатний для міста. Коли столиці розміщені всіма
гравцями, стан детерміновано переходить до економічної фази.

Економіка веде окремий баланс монет для кожного гравця та детермінований журнал.
У фазі економіки нараховується базовий дохід міста й модифікатор місцевості, дохід
будівель та списуються утримання армій і будівель. Після розрахунку світ переходить
до фази будівництва.

Піхота, лучники, кіннота й корабель створюються з конфігурації. Вона є єдиним
джерелом HP, шкоди, дальності, руху, ціни та утримання. Стан світу зберігає лише
ідентифікатор типу, власника, поточний стан і розташування конкретної одиниці.
